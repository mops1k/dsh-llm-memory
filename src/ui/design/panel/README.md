# LLM Memory — общий дизайн панели

Исходники панели, которую отдают Kilo и OpenCode. Экраны, колонки, метрики, поля настроек, действия,
пагинация и подписи приходят из UI SDK плагина (`ui-schema.ts`, `settings-schema.ts`, `ui-contract.ts`), а не
переписаны руками. Это тот же дизайн, что прошёл визуальную приёмку как `panel-ui-prototype`.

В хостах панель работает в двух режимах:

- **embedded** — `scripts/build-panel.mjs` собирает модули в один файл `src/ui/design/panel.html`
  (CSS и JS инлайном); его вшивают бандлы Kilo и OpenCode. Хост передаёт `window.__LM_PANEL__`
  (`kind`, `apiBase: /api/legacy`, `locale`), данные идут из совместимого JSON API.
- **dev** — `server.mjs` раздаёт исходники как есть: демо-хранилище в памяти или живой DSH API через прокси.
  Этот режим нужен для разработки дизайна и в боевую панель не попадает.

## Сборка и встраивание

```bash
node scripts/build-panel.mjs   # -> src/ui/design/panel.html (один файл для Kilo и OpenCode)
pnpm build                     # tsc + web-ui.js + panel.html + бандлы kilo/opencode + client
```

`window.__LM_PANEL__` задаёт транспорт: `kind` (`kilo`/`opencode`), `apiBase` (`/api/legacy`) и `locale`
(`ru`/`en`). Транспорт панели (`js/api.js`, `createLegacyApi`) ходит в `/api/legacy/*`
(`src/adapters/panel/legacy-api.ts`), загружает оба языка схемы и правит настройки через `PUT /settings`.

## Запуск (dev)

Нужен только Node.js ≥ 22 — ни сборки, ни зависимостей.

```bash
node src/ui/design/panel/server.mjs
# http://127.0.0.1:4173/
```

Демо-режим: синтетическое хранилище на 47 записей в памяти процесса, реальные данные не читаются и не
изменяются. Все действия (lint, heal, бэкапы, модель, настройки) работают в памяти и сбрасываются при
перезагрузке страницы.

### Живой режим (DSH)

DSH не отдаёт CORS-заголовки, поэтому страница ходит в API через тот же сервер-прокси:

```bash
node src/ui/design/panel/server.mjs --port 4174 \
  --api http://127.0.0.1:3080/llm-memory/api
# http://127.0.0.1:4174/
```

Проверено на живом хранилище DSH: обзор, записи, поиск, граф, карта RAG, здоровье, бэкапы, модель.
Ограничения live-режима перечислены ниже.

## Что внутри

- **10 экранов SDK**: обзор, записи, поиск, граф знаний, карта RAG, здоровье, настройки, бэкапы, модель
  и редактор записи. Редактор не занимает пункт меню: он открывается из записи или кнопкой «Новая запись».
- **Пагинация и разметка из схемы**: «Записи» — 12/24/48/96, «Поиск» — 10/20/50; колонки, KPI и поля
  редактора берутся из виджетов SDK.
- **Настройки**: 4 группы и 35 полей из `settings-snapshot`; значения по умолчанию из `DEFAULT_CONFIG`.
  Поиск по полям, отметка «после рестарта», dirty-бар, сброс и сохранение.
- **Действия**: 13 из реестра SDK. Опасные (`backup.restore`, `backup.delete`, `model.remove`) требуют
  ввода слова из `confirm`, остальные — обычного подтверждения.
- **13 операций SDK**: `status`, `projects.list`, `items.list`, `items.get`, `graph`, `lint.report`,
  `heal.report`, `health`, `backup.list`, `model.status`, `settings.snapshot`, `vectors.health`,
  `vectors.map` плюс гибридный `recall` для поиска.

## Дизайн и удобство

- Спокойная нейтральная палитра, один акцент, без градиентов на контенте; светлая, тёмная и системная темы.
  Тёмная тема повторяет угольную гамму DSH (`#151517`/`#1b1b1c`, приглушённый синий акцент `#7aaaff`/`#4b5e82`),
  светлая не менялась. Тема применяется до первой отрисовки — без вспышки белым.
- Навигация сгруппирована: «Данные», «Анализ», «Система» — девять пунктов вместо плоского списка из десяти.
- Один основной акцент на экран: «Новая запись», «Создать бэкап», «Скачать модель»; всё остальное — вторичные
  и ghost-кнопки.
- Группа кнопок в шапке карточки стоит отдельной строкой в правом верхнем углу, заголовок и подзаголовок —
  под ними; на узкой карточке кнопки переносятся, а не наезжают на текст (экран «Здоровье»).
- Подробности — в выдвижной панели (запись, архив), чтобы таблицы оставались лёгкими.
- Command palette (`Ctrl/Cmd+K`): переходы, действия SDK, поиск записей, темы и язык.
- Горячие клавиши: `/` — фокус в поиск, `?` — справка, `Esc` — закрыть верхний слой.
- Темы, язык, проект и размер страницы запоминаются в `localStorage`; фильтры списка — в hash URL.
- Адаптив: на ширине ≤ 880 px сайдбар уезжает в drawer, таблицы скроллятся, формы становятся в одну колонку;
  проверено на 420 px.
- Доступность: focus-visible, aria-подписи, клавиатурный выбор строк таблицы и узлов графа, `prefers-reduced-motion`.

```

├── index.html              # оболочка, инлайн-спрайт иконок, тема до paint
├── server.mjs              # статика + прокси /api/* в живой DSH (ноль зависимостей)
├── styles/
│   ├── tokens.css          # токены светлой и тёмной темы
│   └── app.css             # компоненты
├── js/
│   ├── main.js             # загрузка SDK (хост или фикстура), навигация, роутер, palette, хоткеи
│   ├── state.js            # состояние приложения, локализация, тема
│   ├── router.js           # hash-роутинг
│   ├── i18n.js             # строки оболочки (ru/en); данные уже локализованы SDK
│   ├── api.js              # demo/live/legacy транспорт, снимок схемы хоста
│   ├── demo.js             # синтетическое хранилище для dev-сервера
│   ├── ui.js               # таблица, формы, модалки, drawer, тосты, палитра
│   ├── util.js             # DOM/форматы/markdown
│   └── views/              # по файлу на экран SDK
├── fixtures/
│   └── sdk-snapshot.json   # снимок SDK для dev-режима (генерируется, не править руками)
└── scripts/
    ├── gen-fixtures.mjs    # сборка фикстуры из собранного lib/
    ├── smoke-demo.mjs      # проверка демо-транспорта без DOM
    └── check-sdk-parity.mjs# фикстура против собранного SDK и (--live) хоста
```

Собранный файл лежит уровнем выше: `src/ui/design/panel.html` — его читают `scripts/build-kilo.mjs` и
`scripts/build-opencode.mjs` и вшивают в бандлы плагинов.

## Источник правды: SDK-фикстура

`fixtures/sdk-snapshot.json` — это вывод самого SDK, без ручной разметки:

- `locales.{ru,en}.views` — `localizedViews(locale)` (экраны, виджеты, колонки, пагинация);
- `locales.{ru,en}.actions` — `localizedActions(locale)`;
- `locales.{ru,en}.settingsGroups` — `localizedSettingsGroups(locale)`;
- `values` — значения `DEFAULT_CONFIG` по dotted-путям, домашний каталог нормализован в `~`.

Пересобрать после изменения схемы плагина:

```bash
pnpm build
node src/ui/design/panel/scripts/gen-fixtures.mjs
```

Фикстура покрывает 10 экранов, 4 группы настроек, 35 полей и 13 действий — столько же, сколько отдаёт живой
`GET /llm-memory/api/ui/snapshot` (проверяется скриптом паритета).

## Проверки

```bash
node src/ui/design/panel/scripts/smoke-demo.mjs        # операции демо-транспорта
node src/ui/design/panel/scripts/check-sdk-parity.mjs  # фикстура против собранного SDK в lib/

# опционально: сверить с живым хостом (сначала перезапустите его на текущей сборке)
node src/ui/design/panel/scripts/check-sdk-parity.mjs --live \
  http://127.0.0.1:3080/llm-memory/api/ui/snapshot
```

Сверка по умолчанию идёт с собранным SDK и всегда должна проходить; live-сверка показывает, совпадает ли
запущенный хост с текущей сборкой. Если хост старше — он отдаёт старый снимок, и это видно в отчёте.

Прототип проверен в Chromium (headless): все 10 экранов, светлая и тёмная темы, 1440 px и 420 px, оба режима
(демо и live на реальном хранилище 1187 записей), консольных ошибок нет. Интерактивно проверены: фильтр по
проекту, поиск, сохранение настроек, создание/поиск/забывание записи, применение heal, создание/проверка/удаление
бэкапа, удаление и скачивание модели, palette-действие, сохранение темы после перезагрузки, переключение языка.

## Live-режим: что важно знать

- **Встроенная панель (Kilo/OpenCode)**: настройки редактируются через `PUT /api/legacy/settings`; значения и
  список неприменимых путей приходят из `settings/snapshot`.
- **Dev-прокси на DSH**: настройки только для чтения — DSH хранит их в своём settings-сервисе, отдельного
  HTTP-эндпоинта для сохранения у панели нет.
- `GET /api/status` в DSH игнорирует `?project=`; KPI обзора в dev-режиме остаются глобальными, фильтр проекта
  применяется к записям, поиску, графу и карте.
- Поиск в dev-режиме вызывается через `POST /api/recall`; карта — `GET /api/vectors/map` +
  `POST /api/vectors/map/query`. В legacy-режиме это `GET /recall?q=` и `GET /vectors/map?q=`.
- Граф ограничивает отрисовку 120 самыми связанными узлами: полноценный force layout на живом сторе
  нечитаем. В заголовке видно «показано 120 из 1187».
- Записи и опасные действия меняют **реальное** хранилище. Демо-режим ничего не трогает.

## Проверено

Панель проверена в Chromium (headless) против временного стора Kilo: все 10 экранов, светлая и тёмная темы,
1440 px и 420 px, ошибок в консоли нет. Сборка `src/ui/design/panel.html` проверяется тестом страницы
(`tests/panel-page.test.ts`) и `kilo-runtime`/`opencode-legacy-server`.

DSH-поверхности (в оболочке и страница `/ui`) живут отдельно — у них React-реализация на тех же токенах.
