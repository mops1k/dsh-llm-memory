# Release notes

## 2.0.1 — 23.10.2026

Патч-релиз панели: проверка памяти больше не показывает ложные битые ссылки, а
«Применить безопасные исправления» не может удалить валидные связи. Breaking changes нет:
схема БД, формат страниц и имена инструментов не менялись.

| `dsh-llm-memory-2.0.1.tgz` | DSH | npm-пакет: плагин, bundle-patch `cordis.patch.yml`, браузерный клиент, встроенные правила |

### Исправлено

- **Ложные битые ссылки при выбранном проекте.** `/lint` панели фильтровал записи по
  проекту и резолвил ссылки только внутри этой выборки, поэтому ссылки на записи других
  проектов и глобального слоя (`project = ''`) выглядели битыми. Теперь ссылки
  резолвятся по всей памяти, а сам отчёт остаётся в рамках выбранного проекта.
- **`apply-safe` больше не трогает валидные межпроектные ссылки.** `selfHeal` получил
  явный набор известных id (`knownIds`): даже при проектной выборке ссылка проверяется
  по всей памяти. Раньше `apply-safe` с переданным проектом удалил бы такие ссылки как
  «битые».
- **`MemoryService.lint(project)`** резолвит ссылки так же, поэтому исправление
  действует и на MCP-поверхности, а не только в HTTP-панели.

### Обновление

1. Сделайте бэкап памяти (`.llmmem` из панели или CLI).
2. Замените артефакт своего хоста (см. установку в README).
3. Перезапустите хост. Для Kilo это обязательно: страница панели встроена в тело плагина.
4. Проверьте `llm_memory_status` и `llm_memory_lint`; убедитесь, что recall возвращает
   записи.

### Проверено

- `pnpm typecheck`, `pnpm lint`, полный тестовый набор (530 тестов), сборка бандлов;
  CI-матрица Ubuntu и Windows, Windows-смоук собранных бандлов.
- Живая копия стора Kilo: проект `tv2.local` — 152 записи / 130 активных, было 7 ложных
  битых ссылок, стало 0; `apply-safe` сохранил все 317 ссылок проекта.
- `sha256sum -c checksums.txt` по скачанным артефактам.
