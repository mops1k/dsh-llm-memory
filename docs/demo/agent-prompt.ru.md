# Витрина dsh-llm-memory: три промпта, пять минут

Три сессии в одном каталоге `~/Development/snake-demo`. П2 и П3 отвечают на один и тот же вопрос:
первая — читая файлы и **не** используя память, вторая — только из памяти и **не** открывая файлы.

## Промпты

**П1 · сессия 1 — создаёт проект и наполняет память**

```
Сделай в этом каталоге змейку: один файл snake.html, HTML+CSS+JS, без библиотек.
Потом запиши в долговременную память решения проекта и покажи id записей.
```

**П2 · сессия 2, тот же каталог — знание из файлов, память запрещена**

```
Расскажи про проект в этом каталоге: стек, структура, ключевые решения — прочитав файлы,
без использования долговременной памяти.
```

**П3 · сессия 3, тот же каталог — то же знание, но только из памяти**

```
Не открывай файлы проекта. Расскажи про него то же самое, только из долговременной памяти.
```

## Что смотреть

| Прогон | Что подтверждает | Доказательство |
| --- | --- | --- |
| П1 | `llm_memory_save`: kind, tier, scope, importance, связи | id, titles, kind/scope/tier в ответе агента; печатает их он сам или `llm_memory_recall` — инструмент путь страницы не отдаёт |
| П1 | страницы лежат на диске как markdown | `ls -R ~/Development/snake-demo/.dsh/llm-memory` (раскладка `<kind>/<title-slug>-<id>.md`); кросс-проектные — `~/.dsh/llm-memory/_user/**` |
| П2 | файловый путь память не использует | в транскрипте есть `read`/`glob`/`grep` и ни одного `llm_memory_*` |
| П3 | память работает без файлов | в транскрипте только `llm_memory_recall`, ни одного чтения файлов; ответ совпадает с П2 по существу |
| П3+ | усиление: файлы недоступны | перед П3 в сессии 2 переименовать: `mv snake.html snake.html.bak` — тогда память единственный источник |

Ключ проектных записей — basename каталога, поэтому П3 запускается **в том же каталоге**, что П1.
Вкладка **LLM Memory** в оболочке dsh показывает те же записи: Search & Browse, Graph (рёбра
`supersedes`/`related`), Status, Lint, Health.

## Токены

Открыть статистику сессии в чате (строка статистики под перепиской → диалог → блок расхода токенов)
и записать по каждому прогону «всего токенов» и число ходов.

| Прогон | Всего токенов | Ходов | Чем платили |
| --- | --- | --- | --- |
| П1 (создание) | | | код игры + записи в память |
| П2 (файлы) | | | чтение всего кода при каждом вопросе |
| П3 (память) | | | несколько записей из памяти |

Цена самой памяти в токенах: `wc -c` по страницам `.dsh/llm-memory/**` и `~/.dsh/llm-memory/_user/**`,
разделить на 4 — это оценка (в смешанном ru/JS тексте реально 3–5 символов на токен), а не измерение.
Смысл показа: П2 платит за весь код, П3 — за несколько записей, при том же ответе.

## Добавки по одной строке (по желанию)

- **Развилка:** `Передумал: рекорд храним в JSON-файле рядом с игрой, а не в localStorage.` →
  новая запись с `supersedes`, у старой страницы `status: superseded` и `supersededBy`.
- **Гигиена:** `Покажи статус памяти, прогони lint и heal.` → `status` + `lint` + `heal` за один ход.
- **Проверка на выдумку:** `На каком фреймворке сделаны мои игры?` → честное «в памяти этого нет».

## Сброс

`rm -rf ~/Development/snake-demo/.dsh/llm-memory`, затем удалить демо-записи слоя `user` по id из П1
(`llm_memory_delete`). Индекс `~/.dsh/llm-memory/_db/memory.db` пересобирается через `llm_memory_heal`.
Страницы других проектов не трогать.
