# Настройки и семантический поиск (RAG)

Технические детали, вынесенные из README: где менять настройки, что означает каждый ключ,
как устроен гибридный поиск и как загрузить локальную модель. Установка описана в README,
общая схема настроек для панелей — в [ui-sdk.md](ui-sdk.md), RAG в Kilo —
в [adr/p6-acceptance.md](adr/p6-acceptance.md).

## Где менять настройки

- **DSH**: **Settings → LLM Memory** (нативные формы), значения применяются после
  перезапуска плагина.
- **Kilo / OpenCode / MCP**: вкладка настроек в панели (8787 / 8788 / 8789), изменения
  сохраняются в JSON-конфиг и, где нужно, применяются к векторной ноге на месте.

Страница DSH рисуется собственным клиентским бандлом (`client/client.js` → `lib/client.js`):
новое поле схемы требует записи в форме, вызова сохранения через `scope.set` и разметки.
Поля объявлены `volatile()` — сервис настроек DSH принимает правки только по volatile-путям
(иначе `Config field … is not volatile`). Cordis отдаёт volatile-значения реактивными
обёртками, плагин разворачивает их (`unwrapSettings`) при старте.

Настройки эмбеддингов в DSH-схеме **плоские** (`embeddingsProvider`, `embeddingsDim`, …);
`toMemoryConfig` сворачивает их в форму ядра (`embeddings: { provider, dim, … }`).

## Ключи DSH-настроек

| Опция | По умолчанию | Что делает |
| --- | --- | --- |
| `storageRoot` | `$DSH_HOME/llm-memory` | Корень памяти (пусто — значение по умолчанию). |
| `recallLimit` | `10` | Сколько записей возвращает `llm_memory_recall`. |
| `recallFormat` | `markdown` | Формат recall по умолчанию (`markdown`, `table`, `timeline`, `json`). |
| `recallAllowFormatOverride` | `true` | Разрешить агенту менять формат на вызов. Выкл. — фиксирует `recallFormat`, и описание инструмента об этом говорит. |
| `recallLiteralLookup` | `true` | Литеральный запрос (код ошибки, версия, имя файла, id) ранжируется лексической ногой. Замер: закрывает 18 п.п. hit@1 на точных токенах без влияния на семантические запросы. |
| `promptRulesLimit` | `6` | Максимум строк rules/preferences в системном промпте: дайджест уходит в каждый запрос, поэтому он маленький. |
| `rulesPromptScope` | `project` | Охват дайджеста: `project` — кросс-проектный слой `user` + текущий проект, `all` — все проекты. |
| `recallScope` | `project` | Слой recall по умолчанию: `project`, `user` или `all`. |
| `autonomous` | `true` | Агент ведёт память без вопросов. |
| `requireConfirmation` | `false` | Спрашивать перед необратимыми операциями. |
| `systemPrompt` | встроенный (EN) | Текст-инструкция в системный промпт агента. |
| `lintOverlapMinCommonWords` | `8` | Порог пересечения для отчёта lint. |
| `lintMaxPairs` | `200` | Максимум пар для lint (0 — без лимита). |
| `webPath` | `/llm-memory` | Базовый HTTP-путь WebUI и API. |
| `rulesSource` | `bundled-en` | Источник экспорта правил: канонический `bundled-en` или `kilo-verbatim` (оба исходных файла). |
| `embeddingsProvider` | `local` | Источник эмбеддингов: `off` (только FTS5), `local` (модель в процессе), `http` (резерв, не реализован). |
| `embeddingsModel` | `Xenova/multilingual-e5-small` | Id модели для `local` (transformers.js). |
| `embeddingsDim` | `384` | Длина вектора; векторы другой длины пересобираются. |
| `embeddingsBackend` | `js` | Где искать соседей: `js` (скан в процессе), `sqlite-vec` (KNN в SQL, нужен пакет `sqlite-vec`) или `off`. |
| `embeddingsQuantization` | `float` | Точность `sqlite-vec`: `float`, `int8` (в 4 раза меньше) или `bit` (в 32 раза меньше, заметно хуже). |
| `embeddingsTopK` | `50` | Сколько чанков даёт векторная нога до слияния с FTS5. |
| `embeddingsMinScore` | `0` | Минимальный косинус попадания; у e5 косинус сжат, поэтому 0 и ранжирование надёжнее. |
| `embeddingsBatchSize` | `16` | Текстов на один вызов модели при индексации. |
| `embeddingsChunkChars` | `800` | Целевой размер чанка в символах. |
| `embeddingsChunkOverlap` | `120` | Перекрытие соседних чанков (не больше половины размера). |
| `embeddingsSemanticEdgesPerEntry` | `3` | Семантических соседей на запись в графе Wiki. |
| `embeddingsSemanticMaxEdges` | `300` | Общий лимит таких рёбер. |
| `embeddingsPrewarm` | `true` | Грузить модель в фоне при старте, а не на первом запросе. |

### Опция только для профиля

Нативная карточка настроек намеренно не показывает `sessionStartGuide`. Настроить её можно
в патче профиля, если богатая секция системного промпта есть всегда:

```yaml
- id: dsh-llm-memory
  config:
    sessionStartGuide: false
```

После правки перезагрузите/перезапустите плагин: живой reload перестраивает слушателя, но
запущенный плагин не меняет набор слушателей на месте. Остальные профили сохраняют
совместимый дефолт `true`.

## Семантический поиск (векторный RAG)

Recall сливает три ноги через Reciprocal Rank Fusion: FTS5 (BM25), метаданные записи и
косинус по векторам чанков. Вес метаданных низкий (0.1): они не зависят от запроса и только
разрешают ничьи — на реальном сторе вес 1.0 вытеснял релевантные попадания из топа.

Как это работает:

- Векторы даёт локальная модель `Xenova/multilingual-e5-small` (384 измерения, q8) через
  `@huggingface/transformers`; модель кэшируется в `<storageRoot>/_models`, после первой
  загрузки сеть и API-ключ не нужны. Кнопка **Download model** на странице
  **Settings → LLM Memory** (около 130 МБ, с процентом, рядом Check again и Delete cached
  model) качает её в отдельном потоке, чтобы dsh не подвисал. Офлайн-путь тоже работает:
  положите те же файлы в `<storageRoot>/_models/Xenova/multilingual-e5-small`. Пока модели
  нет, поиск идёт по FTS5.
- Инференс ONNX не отдаёт event loop (замер: батч из 64 текстов — 3.4 с без единого тика
  таймера), поэтому индексация идёт в worker-потоке и не блокирует dsh; запрос
  эмбеддится в процессе (~19 мс).
- Страницы режутся на выровненные по предложениям чанки (`chunkChars`/`chunkOverlap`);
  эмбеддится «заголовок + тело чанка», идентичность чанка — хэш текста и модели, поэтому
  неизменные чанки не переэмбеддиваются, а смена модели сама инвалидирует векторы.
- Векторы лежат в `memory_vectors` (канонический float32-кэш). Бэкенд `sqlite-vec`
  дополнительно зеркалит их в таблицу `vec0`: KNN в SQL, фильтры по
  project/scope/kind/tier/status и опциональное квантование.
- Смена бэкенда ничего не переэмбеддивает — производная таблица пересобирается из кэша.
  Смена модели переэмбеддивает записи.

Замеры 2026-10-15 (WSL2, Linux x64, Node v24.20.0, CPU) на копии живого стора — 1059
записей, 3217 чанков × 384 измерения:

| Что | Значение |
| --- | --- |
| Скан в процессе (`js`) | 24.0 мс в среднем, p95 49.4 мс |
| `sqlite-vec` float | 11.6 мс, p95 22.1 мс, 100 % совпадение с `js`, 4.71 МБ |
| `sqlite-vec` int8 | 5.0 мс, p95 8.8 мс, 94.3 % совпадение, 1.18 МБ |
| `sqlite-vec` bit | 1.8 мс, 39.6 % совпадение, 0.15 МБ (экспертный режим) |
| Backfill существующего стора | 1056 записей → 3210 чанков, 4.70 МБ, около 9 минут на CPU |
| Recall self-retrieval hit@1 / hit@5 (40 запросов, k=5) | лексика 70 % / 100 %, гибрид 92.5 % / 100 % |

Свежие замеры этапа 11 (лексическая нога на 1200 записях) — в [perf.md](perf.md).
