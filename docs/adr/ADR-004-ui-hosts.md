# ADR-004: UI-хосты — DSH гибрид (нативные формы + WebUI), остальные общий web

Статус: принято (19.10.2026), уточняет решение №18 ТЗ. Ссылки: ТЗ §5.4, план §5.3, ADR-008.

## Контекст

DSH уже имеет две поверхности: настройки отдаются схемой в `@deepseek-ai/dsh-settings`
(`SettingsForms`, `src/dsh/settings.ts:16`) и рисуются самим DSH, а полноценная WebUI
(статус, записи, граф/карта, lint, backup) отдаётся через `ctx.webServer.register`
(`src/dsh/web.ts:697`, `ui/web-ui.html`, `client/client.js`). ТЗ в решении №18 требовало
«нативные контролы в отдельном окне, без web UI и без `ctx.webServer` для UI». Это
отбросило бы работающую поверхность: формы настроек не показывают граф, карту, браузер
записей и backup-историю.

## Решение

- `packages/ui/headless` — общий слой без React и harness SDK: схемы настроек, view
  models, валидация, i18n, API-клиент, `UiHost`.
- `packages/ui/web` — общие React-экраны для kilocode, OpenCode и MCP; различия только
  темой. Порт по умолчанию: Kilo 8787, OpenCode 8788, MCP UI 8789.
- `packages/ui/theme` — токены и CSS-переопределения, без форков компонентов.
- **DSH — гибрид:** настройки остаются нативными формами DSH через тот же `ui/headless`
  (схема одна), а текущая WebUI-страница сохраняется и переводится на headless view
  models и прямой `DshUiHost` → `MemoryService`. `ctx.webServer` для этой страницы
  остаётся.
- `uiLocale`: `ru`/`en`, выбор при первом старте с сохранением; если выбор пропущен — `en`.
- Web-харнесы получают полную страницу настроек; отдельного «компактного» UI для MCP нет.

## Последствия

- Плюс: DSH не теряет график/карту/backup, а настройки не дублируются в HTML.
- Минус: у DSH две поверхности на одном headless-слое — нужны contract-тесты view models,
  чтобы формы и WebUI не разошлись.
- Отклонено: «полностью нативные формы, WebUI убрать» (теряет функциональность DSH) и
  «WebUI как есть, headless только для логики» (расходится с общей схемой настроек).
