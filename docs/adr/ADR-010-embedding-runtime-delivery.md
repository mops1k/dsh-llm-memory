# ADR-010: доставка рантайма эмбеддингов в Kilo (вариант A)

Дата: 20.10.2026. Статус: принято. Контекст: P4 плана `p_c7de70db394f`.

## Проблема

Kilo-плагин собирается в один файл (`~/.config/kilo/plugin/llm-memory.js`,
2.1 МБ) и исполняется Bun. `@huggingface/transformers` (≈100 МБ с нативными
ONNX-бинарниками) в бандл не влезает, `sqlite-vec` тоже. В `~/.config/kilo/node_modules`
этих пакетов нет (`ResolveMessage`, спайк A3), поэтому векторная нога в Kilo
не работала даже при `embeddings.provider=local` и уже скачанных весах модели.

## Что проверено (спайк A, Windows-хост)

Хост: Windows 10.0.26200.9457; Node v24.19.0; Bun 1.4.3 (Kilo работает на
Bun 1.4.2); Kilo CLI 7.8.13 (один exe, 235 МБ).

1. `npm install @huggingface/transformers@4.3.1` во временный каталог Windows —
   42 пакета, 18 с (сеть есть, реестр доступен).
2. Проба под Node 24 с `env.cacheDir = <Kilo store>/_models`, **полностью
   офлайн** (`allowRemoteModels = false`): модель загрузилась из стора,
   `dims [2, 384]`, косинус «query: язык» / «passage: русский язык интерфейса»
   = **0.8567**, холодный прогон **969 мс**.
3. Та же проба под **Bun 1.4.3** (штатный рантайм Kilo): `dims [2, 384]`,
   косинус 0.8567, **931 мс**. Нативная `onnxruntime-node` в Bun работает.

Вывод: вариант A (пакет ставится рядом с плагином в `~/.config/kilo`) рабочий,
кросс-платформенный по конструкции (`npm` есть везде, где ставится плагин),
весов в сторе достаточно для офлайна.

## Решение

- Рантайм ставится в `~/.config/kilo/node_modules` командой
  `npm install --no-save --no-package-lock @huggingface/transformers@^4.3.1`,
  не в бандл и не в `package.json` хоста (файлы Kilo не трогаем).
- Установка **только по явному действию** «Скачать модель»: при нажатии, если
  пакет не резолвится из плагина, сначала ставится рантайм, затем качаются
  веса (или используются уже лежащие в сторе). На старте плагина — никогда.
- После установки векторная нога пересобирается без перезапуска хоста; при
  неудаче панель показывает ошибку npm и точную команду для ручной установки.
- Если рантайма нет и установка невозможна, остаётся «скачать только файлы»
  (`fallbackDownload`): веса лежат в сторе, поиск работает лексически.

## Отклонённые варианты

- **B. Sidecar-эмбеддер по loopback-HTTP.** Отклонён: A уже работает в штатном
  рантайме Kilo; sidecar добавил бы второй процесс, супервизию, порт и ещё один
  канал отказа, ничего не выиграв по совместимости.
- **C. Платформенные бандлы (win32-x64/linux-x64).** Отклонён: сборка и
  публикация нативных артефактов под каждую платформу, ~100 МБ на пакет, и
  всё равно нужен per-platform CI; A покрывает обе платформы одним способом.
- `optionalDependencies` пакета (`@huggingface/transformers`, `sqlite-vec`)
  остаются как есть: они нужны DSH, а Kilo-рантайм ставится отдельно, потому
  что npm-дерево хоста не обязано совпадать с деревом плагина.

## Откат

`rm -rf ~/.config/kilo/node_modules/@huggingface` (и `node_modules` целиком,
если ставился только он) + `embeddings.provider = "off"`; кэш весов
`<store>/_models` не затрагивается, лексический поиск продолжает работать.

## Риски

- Обновление Bun/Kilo может сломать загрузку `onnxruntime-node`; проверено на
  Bun 1.4.3, версия Kilo 7.8.13. При обновлении повторить пробу из §2.
- npm-реестр за прокси/без сети: установка падает с понятной ошибкой, остаётся
  файловый fallback и ручная команда из панели.
