# ADR-008: решения 19.10.2026 — канон этапов, правило импортов по слоям, поправки к документам

Статус: принято (19.10.2026). Ссылки: ADR-001, ADR-004, ТЗ §8, план §11.

## Контекст

ТЗ и план разошлись в деталях, и до импорта в plan-store нужно было зафиксировать, что
считать каноном. Четыре развилки меняли структуру репозитория и текст требований.

## Решение

1. **Канон этапов — ТЗ §8** (0 baseline → 1 monorepo/core → 2 UI → 3 Kilo parity и
   schema migration → 4 backup/restore → 5 Kilo cutover → 6 DSH adapter → 7 OpenCode →
   8 MCP → 9 векторы → 10 sync-groundwork → 11 hardening) с графом зависимостей
   `0→1→2→3→4→5`, `1→10`, `1→9`, `5→6→7→8`, `2/4→6/7/8`. Порядок §11 плана (backup+Kilo
   на этапе 3, векторы на 4) больше не используется.

2. **Правило импортов core сужается по слоям.** Запрет «core не импортирует
   `@kilocode/plugin`, `@opencode-ai/plugin`, `@deepseek-ai/*`, `bun:*`, `node:sqlite`»
   действует для `domain`, `application`, `layout`, `sync`. Реализации `NodeSqlite` и
   `BunSqlite` живут в `packages/core/src/infrastructure/sqlite` и драйверы используют —
   иначе FR-STORE-01 невыполним. Правило фиксируется в `docs/adr` и проверяется lint/
   contract-тестом на импорты в запрещённых слоях.

3. **Монорепо in-place** — см. ADR-001: текущий репозиторий `dsh-llm-memory` становится
   монорепо, имя пакета и публикация сохраняются.

4. **DSH UI — гибрид** — см. ADR-004: нативные формы настроек + сохранённый WebUI.

Поправки к документам, снятые при baseline (`baseline.md`, `differences.md`):

- `tests/` содержит 29 файлов `*.test.ts` — цифра плана верна; «31» — число записей
  каталога вместе с `helpers.ts` и `tests/helpers/`.
- DSH-ядро использует `node:sqlite` `DatabaseSync` напрямую (`src/core/store.ts:11`) —
  подтверждает пункт 2.
- `~/.config/kilo` на этой машине отсутствует: Kilo-часть этапов 0, 3, 5 выполняется на
  Windows-хосте.
- Runtime для MCP (`node:sqlite` в Node 22 — experimental) остаётся открытым до спайка A11.

Открытые вопросы ТЗ §15 (theme-токены, хранение passphrase, авто-backup, формат review для
sync, UI конфликтов, общий read-only model cache) не блокируют этапы 0–1 и решаются на
своих этапах.

## Последствия

- Плюс: один канон этапов устраняет расхождение плана и ТЗ; правило импортов не мешает
  реализации SQLite-портов.
- Минус: ТЗ §4 и §5.1 остаются с прежней формулировкой запрета — при следующем изменении
  документов её нужно синхронизировать с этим ADR.
